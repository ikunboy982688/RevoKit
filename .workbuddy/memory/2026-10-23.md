## test3：加固特征库按真实样本重建（49 家）

### 数据源
用户提供 `加固特征.zip`（66MB / 553 条目 / **49 家壳目录**，34 家有实物样本，每家带
`加固壳信息.md` 写明被替换的 Application 类 + assets/lib 真实文件名）。
解析脚本在 `/tmp/verify_packer.py`（思路：正则按 `PackerRule(` 分块提取 listOf，再用样本
文件列表跑一遍评分，做**离线回归测试**，不用等 Gradle 编译）。

### 关键结论（推翻我原来的假设）
1. 用户叫法：**「腾讯御安全」**，不叫「乐固」。已改名（乐固只留在源码注释里做说明，dex 里没有了）。
2. **光看 Application 类必误判**：娜迦的桩类也叫 `com.stub.StubApp`（跟 360 一字不差）；
   易固、Frezrik 也都放 `libjiagu.so`。必须 so / assets / appclass 三条腿一起看。
3. 很多壳把 so 藏在 assets 里运行时释放：爱加密 `assets/ijm_lib/<abi>/libexec.so`、
   珊瑚灵御 `assets/libreincp.so`、启明星辰 `assets/venCache/libvenSec.so`。
   **只看 lib/ 目录会漏掉一半**。
4. 有些壳的加密数据直接在 zip 根目录：随风 `src/<md5>`、顶象 `dsnapk0000.vd`、
   阿里聚安全 `aliprotect.dat`、Master-Mu。原来只看 assets/ 完全匹配不到。

### 评分模型（改动后）
`APP_CLASS 50 / SO_LIB 35 / ASSET 30 / MANIFEST_STRING 25 / DEX_STRING 15`，
同类多文件命中每个额外 +5（上限 +10），无实物样本规则 ×0.8，
`hasSample` 用于压分而不是隐藏，`priority` 用于企业版压普通版。
阈值：≥75 确定 / ≥50 高度疑似 / ≥25 疑似。

### 回归结果
49 个目录：**48 个能显示正确名字**（盛大加固只有空目录，无特征可支持）；
38 个 ≥50 分。低分的全是「无实物样本、只有 so 名」的，名字对但置信度标「疑似」——
这是设计如此，不是 bug。

### 踩的坑（重要，以后写 Kotlin 注释必须避开）
**Kotlin 支持嵌套块注释**，所以 KDoc 里出现 `/*` 或 `*/` 会让注释提前闭合/延长，
报错却指向几百行外的 `Missing '}'` + EOF `Unclosed comment`，极难定位。
本次触发点：`/** ... assets/ijm_lib/*/libexec.so ... */`、`lib/*_shell_...`、
`assets/*.dex`、`assets/maindata/*.txt`。修法：注释里把 `*` 换成 `<abi>` / `<name>` / `<pkg>`。
排查手法：逐行取 `/**` 之后、行尾 `*/` 之前的内容，检查是否还含 `/*` 或 `*/`。
